You merged five PDFs. Page 3 of the result should have been page 1. The cover letter ended up at the back. The scanned receipt is upside down.

Merging is easy. Merging **correctly** takes a minute of planning — and saves rework.

## Before You Merge: Plan the Page Order

Write down (or mentally note) the final sequence:

1. Cover letter
2. Main document
3. Appendix A
4. Appendix B
5. Signed page

If your source files don't match this order, reorder **before** merging — not after.

Most merge tools let you drag files into sequence. Use that. Don't assume alphabetical filename order is correct.

## Common Merge Scenarios

### Combining scanned pages

You photographed five pages and converted them to PDF. They should merge in capture order — but camera roll order isn't always chronological. Check the sequence before merging.

### Appending a signature page

Workflow: main document first, signature page last. If the signed page is a separate scan, it goes at the end — not mixed into the middle.

### Merging chapters or sections

Book chapters, report sections, or course modules: merge in reading order. Filename sorting (`chapter1.pdf`, `chapter2.pdf`) usually works — unless someone named them wrong.

### Bundling application materials

Cover letter → resume → portfolio samples → references. Recipients expect this order. Deviating looks unprofessional.

## Handling Mixed Sources

Real merges often combine:

- **Digital PDFs** (exported from Word, Google Docs)
- **Scanned pages** (phone photos converted to PDF)
- **Extracted pages** from larger documents

Tips for mixed sources:

- **Extract first, then merge** — if you need pages 3–7 from a 50-page PDF, [split/extract](/split-pdf) those pages first
- **Normalize size** — scanned pages at different resolutions look inconsistent. Resize images before converting to PDF
- **Check orientation** — phone scans often need rotation. Fix before merging, not after

## When to Split Instead of Merge

Sometimes merging isn't the right move:

- Recipient only needs one section → send that section alone
- File exceeds email size limit → split into parts, not one giant merge
- Different recipients need different sections → create targeted PDFs

Merge when the recipient needs the **complete package** in one file.

## File Size Before Merging

Five 10MB PDFs become a 50MB merge. Check total size before combining:

- Email limit is typically 25MB
- Some portals reject files over 10MB

If size is a concern, compress image-heavy PDFs before merging, or merge then compress the result via [PDF to Image](/pdf-to-image) → [Image Compressor](/image-compressor) → [Image to PDF](/image-to-pdf).

## Removing Unnecessary Pages

Don't merge pages you don't need:

- Blank pages from scanning
- Duplicate copies
- Cover pages from source documents that aren't relevant

[Split](/split-pdf) to extract only what you need, then merge the clean set.

## Encrypting the Final Document

After merging a complete package — especially for client deliverables:

1. Merge in correct order
2. Review the result page by page
3. [Password-protect](/encrypt-pdf) if sending sensitive content
4. Email or share

Encrypt after merging so one password protects the entire document.

## Privacy for Multi-Document Merges

Merges often combine sensitive files — contracts, financials, personal records. Upload-based merge tools receive **every file** in the bundle. That's multiple documents on a stranger's server.

Browser-based merging keeps all source files on your device. Nothing is transmitted during the merge.

## Quick Checklist

- [ ] Final page order planned
- [ ] Source files in correct sequence
- [ ] Scanned pages right-side up
- [ ] Unnecessary pages removed
- [ ] Total file size acceptable
- [ ] Result reviewed page by page
- [ ] Encrypted if sensitive
